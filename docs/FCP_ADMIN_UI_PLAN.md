 FCP Web Admin Interface — Implementation Plan

 Context

 FCP has a mature backend with 50+ REST API endpoints, 16+ storage traits, and 80+ CRUD
 methods, but zero frontend code. This plan builds a comprehensive, enterprise-grade web
 admin interface as a new workspace crate (fcp-admin-ui) with a React/TypeScript SPA
 embedded into the existing fcp-admin Axum server. The SPA talks to the existing /api/v1/
 REST API and WebSocket event stream.

 Serving Strategy

 - fcp-admin-ui/src/lib.rs exports pub fn admin_ui_router() -> axum::Router that:
   - Serves dist/ static files at /admin/assets/
   - Serves index.html as catch-all for SPA client-side routing at /admin/*
   - Uses include_dir! macro to embed built assets into the binary (single binary
 deployment)
 - fcp-admin/src/main.rs merges: .merge(fcp_admin_ui::admin_ui_router())
 - Dev mode: cd crates/fcp-admin-ui/ui && npm run dev → Vite dev server on port 5173 with
 proxy to backend API

 Authentication Flow

 - Login page → POST /api/v1/auth/login → returns JWT token
 - Token stored in httpOnly cookie (set by server) + memory for API calls
 - All API requests include Authorization: Bearer <token> header
 - Token refresh via POST /api/v1/auth/refresh
 - Role info decoded from JWT payload → drives UI permission guards

 Backend Gaps to Fill

 These new endpoints/types are required before or alongside the UI:

 1. Auth Session Endpoints (new in fcp-api-core)

 POST   /api/v1/auth/login          # username + password → JWT + set cookie
 POST   /api/v1/auth/logout         # invalidate session
 POST   /api/v1/auth/refresh        # refresh token
 GET    /api/v1/auth/me             # current user profile + role

 Files: crates/fcp-api-core/src/v1/auth.rs (new), wire into router

 2. API Token Management

 GET    /api/v1/api-tokens          # list tokens for current user
 POST   /api/v1/api-tokens          # create token (returns secret once)
 DELETE /api/v1/api-tokens/:id      # revoke token

 New types in fcp-core: ApiToken { id, name, prefix, hashed_secret, user_id, tenant_id,
 permissions, expires_at, created_at, last_used_at }
 New trait: ApiTokenStore in fcp-core/src/storage.rs

 3. Audit Log

 GET    /api/v1/audit-logs          # paginated, filtered by actor/resource/action/date
 GET    /api/v1/audit-logs/:id      # single entry detail

 New types in fcp-core: AuditEntry { id, tenant_id, actor_id, actor_type, action,
 resource_type, resource_id, changes_json, ip_address, timestamp }
 New trait: AuditLogStore in fcp-core/src/storage.rs
 Middleware: Axum layer that auto-logs write operations

 4. Number Porting API (expose existing PortingManager)

 GET    /api/v1/port-requests                # list all port requests
 POST   /api/v1/port-requests                # create new port request
 GET    /api/v1/port-requests/:id            # get details
 PUT    /api/v1/port-requests/:id            # update
 POST   /api/v1/port-requests/:id/submit     # submit to carrier
 POST   /api/v1/port-requests/:id/cancel     # cancel

 Files: crates/fcp-api-core/src/v1/porting.rs (new) — wraps existing PortingManager

 5. Dashboard Summary Endpoint

 GET    /api/v1/dashboard/summary   # aggregated stats for current tenant

 Returns: { active_calls, registered_devices, total_users, total_extensions,
 total_phone_numbers, calls_today, avg_call_duration, queue_stats, cluster_health }

 File: crates/fcp-api-core/src/v1/dashboard.rs (new)

 6. System Settings CRUD

 GET    /api/v1/settings             # all settings for tenant
 PUT    /api/v1/settings             # bulk update
 GET    /api/v1/settings/:key        # single setting
 PUT    /api/v1/settings/:key        # update single

 New types: Setting { key, value, tenant_id, updated_at, updated_by }
 New trait: SettingStore

 Feature Modules (Frontend Pages)

 Each module maps to a route and uses existing API endpoints unless noted.

 Module 1: Shell & Auth

 - Sidebar navigation with collapsible sections, role-aware visibility
 - Login/logout pages
 - User profile page (change password, preferences)
 - Global search (cmd+k) — client-side fuzzy search across loaded entities
 - Theme toggle (light/dark) via Tailwind dark: classes
 - Real-time toast notifications via WebSocket connection to fcp-events-server
 - Breadcrumb navigation

 Module 2: Dashboard

 - Summary cards: active calls, registered devices, users, extensions
 - Call volume chart (24h sparkline from CDR data)
 - Queue status overview
 - Cluster health indicators
 - Recent events feed (WebSocket)
 - API: GET /api/v1/dashboard/summary (new), GET /api/v1/calls, CDR queries

 Module 3: Tenants (super-admin only)

 - Tenant list with search, filter, pagination
 - Create/edit tenant form with quota settings
 - Tenant detail page with resource counts
 - API: existing GET/POST/PUT/DELETE /api/v1/tenants

 Module 4: Users & Credentials

 - User list with role badges, status indicators
 - Create/edit user form (role assignment, department, extension link)
 - SIP credentials management (digest password reset)
 - Bulk import (CSV upload → parse → preview → submit)
 - API: existing GET/POST/PUT/DELETE /api/v1/users, POST /api/v1/users/:id/credentials

 Module 5: Extensions

 - Extension list with quick-filter by range
 - Create/edit extension form
 - Bulk create (range-based: 1000-1099)
 - API: existing GET/POST/PUT/DELETE /api/v1/extensions

 Module 6: Devices

 - Device list with type/vendor/status filters
 - Create/edit device form (MAC address, vendor, model, template)
 - Provisioning template viewer/editor
 - API: existing GET/POST/PUT/DELETE /api/v1/devices

 Module 7: Phone Numbers & E911

 - Number inventory with search, filter by type/status
 - Assign/unassign numbers to tenants
 - E911 address management (address validation UI)
 - Number porting tab: port request list, create, status tracking
 - API: existing phone number endpoints + new porting endpoints

 Module 8: Line Bindings

 - Binding list showing extension ↔ device ↔ number relationships
 - Visual binding editor: drag to connect extensions, devices, and numbers
 - Quick-bind form for simple cases
 - API: existing GET/POST/PUT/DELETE /api/v1/line-bindings

 Module 9: Routing & Policy

 - Dial plan rules table with drag-to-reorder priority
 - Rule editor form (pattern, action, time conditions)
 - Policy rules list (rate limits, call restrictions)
 - Time-of-day routing visual schedule editor
 - API: existing GET/POST/PUT/DELETE /api/v1/routing/rules

 Module 10: SIP Trunks & SBC

 - Trunk list with health indicators (up/down/degraded)
 - Create/edit trunk form (transport, credentials, codecs, SRTP, STIR/SHAKEN)
 - Trunk quality dashboard (ASR, ACD, PDD metrics)
 - SBC admission policies editor
 - API: SBC admin endpoints at fcp-sbc /admin/trunks, /admin/admission, /admin/quality

 Module 11: Call Control & Live Ops

 - Active calls real-time table (auto-refresh via WebSocket)
 - Call detail drawer (participants, duration, codec, media stats)
 - Live actions: transfer, hold/resume, mute/unmute, record start/stop, hangup
 - Call history with date range picker and filters
 - API: existing call management endpoints + CDR endpoints

 Module 12: IVR / Flow Builder

 - Flow list with version indicators
 - Visual flow editor using React Flow:
   - Node types: Answer, Play, Gather, Dial, Queue, Voicemail, HTTP, Branch, Hangup
   - Drag-and-drop from palette
   - Connection validation (output types match input types)
   - Property panel for selected node configuration
   - JSON export/import
 - Flow version history (list versions, activate, rollback)
 - API: existing GET/POST/PUT/DELETE /api/v1/flows

 Module 13: Voicemail

 - Mailbox list with message counts
 - Mailbox detail: messages table, greeting management
 - Message player (inline audio playback)
 - Greeting upload (file upload form)
 - API: existing voicemail endpoints

 Module 14: Queues & ACD

 - Queue list with real-time stats (waiting, talking, available agents)
 - Queue detail: agent roster, live call queue, historical stats
 - Agent management: add/remove agents, set skills, toggle availability
 - API: existing queue endpoints + agent endpoints

 Module 15: Presence

 - Presence status grid (all users, color-coded: available/busy/away/dnd/offline)
 - Set presence for current user
 - Presence history timeline
 - API: existing presence endpoints

 Module 16: Monitoring & Observability

 - Cluster overview: node cards with health status, uptime, active calls
 - Node detail: system metrics, active calls on node, config
 - Prometheus metrics dashboard (key metrics rendered as charts from /metrics)
 - Event log viewer: real-time event stream with filters (WebSocket)
 - API: cluster health endpoints, /metrics, event WebSocket

 Module 17: CDRs & Analytics

 - CDR search with advanced filters (date range, caller, callee, disposition, duration)
 - CDR detail page (full record with call flow timeline)
 - Export to CSV (client-side generation from search results)
 - Analytics charts: calls per hour/day, average duration, top callers, disposition
 breakdown
 - API: existing CDR endpoints

 Module 18: Audit Log (requires new backend)

 - Audit log table: who, what, when, where
 - Filters: by actor, resource type, action, date range
 - Detail view: full change diff (before/after JSON)
 - API: new audit log endpoints

 Module 19: Settings

 - System settings editor (key-value with typed inputs)
 - API token management: list, create, revoke
 - Feature flags viewer (future)
 - API: new settings + API token endpoints
